## Prisma / DB (critical)

- **PostGIS must be installed** before running migrations or seeds: `CREATE EXTENSION IF NOT EXISTS postgis;` on the target DB.
- **`prisma/constraints.sql`** is the FINAL-STATE reference for CHECKs, triggers, and partial indexes that Prisma cannot model. It is not appended to any migration. Deployed databases get changes only via migrations, so every change to `constraints.sql` needs a migration carrying the same SQL (v6: `20261107000300_v6_constraints`, `20261107000400_v6_validate`, `20261107000500_v6_contact_unique`, `20261111000100_pr1_hardening`; PR B: `20261116000300_edu_constraints`, `20261116000400_edu_validate`; payments: `20261121000100_payment_attempts`, `20261121000200_payment_attempts_validate`, `20261122000100_promo_codes`, `20261123000100_refunds`, `20261123000200_refunds_validate`, `20261126000100_upload_moderation`, `20261126000200_upload_moderation_validate`; phone OTP: `20261127000100_phone_otp`, `20261127000200_phone_otp_validate`; matching: `20261128000100_matching`, `20261128000200_matching_validate`; stories: `20261129000200_stories`, whose CHECKs are inline in CREATE TABLE and repeated in constraints.sql section 25).
- Review generated SQL and **never accept a DROP INDEX** for: `tutor_name_trgm`, `notification_due_idx`, `tutor_location_geog_gist_idx`, `student_location_geog_gist_idx`, `tutor_zone_center_gix`, `dispute_raised_by_idx`, `tutor_requirement_one_default`, `zlr_one_pending_per_tutor`, `fee_payment_gateway_ref_uniq`, `payment_attempt_one_pending_per_fee`, `promo_redemption_one_active_per_fee`, `payment_refund_one_open_per_attempt`, `payment_refund_ref_uniq`, `upload_block_one_active`, `city_boundary_gix`, `requirement_invite_requirement_id_tutor_id_key`, `story_one_pending_per_account`. Prisma also proposes dropping DEFAULTs on location ids; ignore that.
- The test setup (`src/tests/setup.ts`) runs `npx prisma migrate deploy` before each test suite. Tests use a real PostgreSQL DB with PostGIS.
- Test DB: set `TEST_DATABASE_URL` in `.env` (format: `postgresql://user:password@localhost:5432/tuition_test?sslmode=disable`). Tests use `TEST_DATABASE_URL` when set, otherwise `DATABASE_URL`.
- Vitest config uses `pool: "threads"` and `fileParallelism: false` — tests are not parallelized.
- **File upload migrations:** `20261124000100_file_uploads` and `20261124000200_file_uploads_validate` add `file_asset.original_name` and `published_at`, the student verification columns, and the foreign key `student_verification_reviewed_by_fkey` (added NOT VALID, then validated). They add no CHECKs, triggers or indexes, so `constraints.sql` is unchanged.
- **Migration safety:** rehearse pending migrations with `bash scripts/migrate-safe.sh '<prod direct url>'` (`--drill` = restore check only). It dumps prod, restores to a local scratch DB, applies the migrations there, and writes `.backups/.rehearsed`. Prod is only read. Full guide: `docs/migrations.md`.
- **Pre-push gate:** `.husky/pre-push` blocks a push that changes `prisma/migrations` unless `.backups/.rehearsed` matches the current migration files. `git push --no-verify` skips ALL checks; never use it for an unrehearsed migration.
- **Squawk:** `yarn lint:sql` runs in CI on new migrations only. The 9 existing ones are in `excluded_paths` in `.squawk.toml`; never add new migrations there. Silence a deliberate warning with `-- squawk-ignore <rule>`.
- **Backups:** `.backups/` is gitignored and holds PII dumps. Dumps older than 14 days are deleted automatically.
- **Agents never run `migrate-safe.sh` against production.** It needs the user's prod URL and a DO Trusted Sources IP; ask the user first.
- **Database session time zone:** the Prisma pg driver adapter sends a JS Date as a wall-clock time without an offset, which Postgres reads in the session time zone. On a Postgres server whose TimeZone is not UTC (the local one was Asia/Dhaka) every Date the app wrote or compared was shifted by the zone offset (6 hours), while columns filled by Postgres `now()` defaults were not, so stale-checkout and time-window queries were wrong. Direct (non-pooled) connections now start with `-c TimeZone=UTC` next to the existing `statement_timeout` options. Pooled URLs cannot pass startup options and rely on the database default, which must be UTC (DigitalOcean managed Postgres defaults to UTC; check with `SHOW timezone`). New test `src/lib/prisma-timezone.test.ts` fails if a connection is not in UTC or a Date drifts from `now()`. Local rows written before this fix carry times 6 hours early.

## Lint / Typecheck / Test order

The pre-push hook and CI enforce: **`lint -> typecheck -> openapi:check -> test:ci -> build`**. Always run in this order on a PR. Skipping any step may cause the hook or CI to fail. The pre-push hook also runs the migration rehearsal gate first when `prisma/migrations` changed.

## Environment variables (from .env.example)

Required for the app to start:
- `DATABASE_URL` is the direct URL (port 25060), used by migrations and the Prisma CLI. There is no `DATABASE_DIRECT_URL`; do not add one.
- `DATABASE_POOL_URL` is the app's pool URL (optional; falls back to `DATABASE_URL`). The app owns its `pg.Pool` (`src/lib/prisma.ts`): max 3 per process (override with `?connection_limit=`), 5 s connect timeout, 10 s `statement_timeout` on direct URLs.
- `ACCESS_TOKEN_SECRET` (min 32 chars)
- `REFRESH_TOKEN_SECRET` (min 32 chars)

Required once auth/files/notifications are used:
- `GOOGLE_CLIENT_ID`
- `R2_ENDPOINT`, `R2_REGION`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`. Storage counts as configured only when `R2_ENDPOINT`, `R2_BUCKET`, `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY` are all set (`storageConfigured()` in `src/lib/storage.ts`). Without them the upload-url, complete and download-url routes answer 503 STORAGE_UNAVAILABLE, the public video and blog lists return `url: null`, and the cleanup cron does nothing.
- `N8N_WEBHOOK_URL`, `N8N_WEBHOOK_SECRET`
- `SUPER_ADMIN_EMAIL_1`, `SUPER_ADMIN_EMAIL_2`

Optional:
- `API_DOCS` — `true` | `false`. Enables Swagger UI at `/docs`. Default: on outside production, off in production.
- `SSLC_STORE_ID`, `SSLC_STORE_PASSWORD`, `SSLC_IS_LIVE` ("true"/"false", default "false"; the app refuses to boot with "true" unless NODE_ENV=production), `SSLC_BASE_URL` (informational only), `API_PUBLIC_URL` (base for gateway callback URLs), `WEB_PUBLIC_URL` (where the browser returns). Payments count as configured only when store id, store password, API_PUBLIC_URL and WEB_PUBLIC_URL are all set.
- `SMS_KEY` (sms.net.bd API key), `SMS_BASE_URL` (default `https://api.sms.net.bd`), `SMS_DRY_RUN` (`true` | `false`). Without a key, outside production, sends are dry runs (development logs the message). With `SMS_DRY_RUN=true` nothing is sent in any environment, and `env.ts` refuses it when NODE_ENV=production (codes would never arrive). In production without a key, sending gives 503 SMS_UNAVAILABLE. Never print the key.
- `R2_PUBLIC_BUCKET` and `R2_PUBLIC_URL_PREFIX` (optional): the public copy is used only when both are set; `R2_PUBLIC_URL_PREFIX` is the public domain of that bucket. Without both, approved videos, blog covers and site media are served through signed URLs valid 1 hour, and `publishFile` does nothing. Production must set both, so landing media are not served through 1-hour signed URLs. At startup, `r2PublicConfigWarnings()` (`src/config/env.ts`, called from `main()` in `src/server.ts`) logs a warning when `R2_BUCKET_PUBLIC` is set but `R2_PUBLIC_BUCKET` is not (a common misspelling), and when only one of the two public settings is set. The warnings name the variables, never print a value, and do not stop the boot. `NEXT_PUBLIC_MEDIA_URL_PREFIX` in tution-media must equal `R2_PUBLIC_URL_PREFIX`.

## Project structure (high-level)

- `src/config/env.ts` — Zod-validated env config (do not rename fields; the schema is the source of truth).
- `src/lib/prisma.ts` — Prisma singleton with CA cert fallback (`ca-certificate.crt` at repo root).
- `src/lib/areas.ts` — helper `unusableAreaIds(db, ids)`; `src/lib/districts.ts` exports `DIVISIONS` and `DISTRICTS` (code -> {name, division}, parity-tested against DISTRICT_CODES).
- `src/modules/` — route handlers by domain (auth, tutor, student, location, phone-verification, etc.).
- `src/lib/sms.ts` — the only SMS provider client (sms.net.bd). See Phone verification below.
- `src/plugins/` — Fastify plugins (auth, health) and the response cache helpers (`cache.ts`).
- `src/openapi/` — Swagger/OpenAPI 3.1 plugin, docs, export, and contract tests.
- `src/server.ts` — app entry point; registers all plugins and routes.
- `src/seed/index.ts` — seeds areas, subjects, and super-admin emails.
- `src/cron/weekly-location-expiry.ts` — weekly cron that soft-warns (≥21 days) and hard-expiries (≥28 days) tutor/student locations.
- `src/cron/fee-reminders.ts` — daily cron that enqueues PAYMENT_REMINDER outbox rows for unpaid placement fees.
- `src/cron/payment-reconcile.ts` — cron that runs every 10 minutes (UTC) and calls `runPaymentReconcile()` in `src/modules/payment/payment-reconcile.service.ts` to re-check stale PENDING SSLCommerz attempts.
- `src/cron/file-cleanup.ts` — daily cron (04:00 UTC) that calls `runFileCleanup()` in `src/modules/files/file-cleanup.service.ts` to expire abandoned uploads, drop unused files and purge deleted ones.
- `src/cron/phone-otp-cleanup.ts` — daily cron that calls `runPhoneOtpCleanup()` in `src/modules/phone-verification/phone-otp-cleanup.service.ts` to delete `phone_otp` rows created more than 24 hours ago. Nothing reads a row that old.
- `dist/` — production build output.
- `prisma/migrations/` — generated migrations; `prisma/constraints.sql` is the hand-edited final-state reference (see Prisma / DB).

## Testing quirks

- Tests hit a **real PostgreSQL database** with PostGIS enabled. Do not run tests against an in-memory or empty DB — they will fail.
- The test setup truncates 50+ tables in `beforeEach`. If you add a new model/table, add it to the TRUNCATE statement in `src/tests/setup.ts`. The list already includes the v6 tables, `payment_attempt`, (upload moderation) `upload_review` and `upload_block`, and `phone_otp`.
- `platform_setting` is seeded by migration, so TRUNCATE CASCADE wipes it. `setup.ts` re-seeds it in `beforeEach`; keep that when editing the list.
- `prisma.config.ts` uses `TEST_DATABASE_URL` as the shadow DB, so `migrate dev` resets the test DB.
- Factories in `src/tests/helpers.ts` (createAccount, createStudentProfile, createTutorProfile, etc.) are the canonical way to create test data.
- `setTutorLocation` and `setStudentLocation` in `src/tests/helpers.ts` insert location rows with PostGIS `ST_SetSRID(ST_MakePoint(...))`.
- To add a new test helper, add it to `src/tests/helpers.ts` — do not create parallel test data utilities.
- New helpers: `createAdmin({status, adminRole})` creates an allowlisted active SUPER_ADMIN approver as needed (admin_user CHECKs require an approver for ACTIVE/REMOVED admins); `createZoneLimitRequest(tutorId, {...})` creates a zone limit request row. `createSuperAdmin()` get-or-creates the active super admin. `createPlatformFee()` and `createFeePayment()` for fee testing. `createTuitionPackage` accepts moderationStatus, moderationNote, createdAt. `createFakeGateway()` ({ gateway, sessions, setValidation, setQuery, failNext, refunds, setRefundAnswer, setRefundQuery }), `fakeSuccess({ tranId, valId, amount })`, `createTutorFeeFixture(amountDue = 1500)`, `setPlatformSetting(key, value)`.
- `src/tests/payments-journey.test.ts`: three journeys through the real HTTP routes with the fake gateway: (1) settings, quote, promo apply/remove/apply, checkout, success redirect + duplicate IPN (one ledger row), admin views, tutor refund request, super-admin approve + gateway check (one REVERSAL row, fee DUE again), waive; (2) gateway down at checkout (503, no PENDING left), retry, POST /fail, late validated IPN still settles; (3) amount mismatch → REVIEW, reject → UNAPPLIED, admin refund, both reconcile crons → SUCCEEDED with no ledger row; audit entries checked.
- `src/lib/prisma-timezone.test.ts`: fails if a connection is not in UTC or a Date drifts from `now()`.
- File helpers: `createFileAsset(ownerAccountId, purpose, overrides?)` makes an UPLOADED row by default; override `status`, `storageKey`, `uploadedAt`, `publishedAt`, `originalName` and the rest as needed. `createFakeStorage({ publicBucket? })` returns `{ storage, objects, publicObjects, presignedPuts, put(key, bytes, contentType), failNext(err?) }`; install it with `setStorageForTests(fake.storage)`. `fakeFileBytes(contentType, size)` starts with that type's bytes from `FILE_SIGNATURES`, so it passes the sniff check. Otherwise storage is off in tests: `setup.ts` deletes every `R2_*` variable and resets storage before each test.
- `tv_decision_shape`: an APPROVED or REJECTED `tutor_verification` row needs `reviewedById` and `decidedAt`, and a REJECTED one needs a note (`tv_rejection_has_note`). Decision fixtures must set all of them.
- **Matching test setup**: `requirement_invite` is in the TRUNCATE list. `city` is NOT truncated: Dhaka is seeded by migration. `setup.ts` deletes every other city, re-activates `dhaka` and resets the matching config cache before each test. Tests must never change the `dhaka` row; use another slug (e.g. `testville`) for city upload tests. `createTutorRequirement` hard-codes `teachesOnline: true`, so with no `zoneIds` the set is online-only and cannot match home tuition: pass `zoneIds` for home tuition.

- **Testing stories and landing cards**: `createStoryRow` (story rows, any status) and `createLandingRow` (a testimonials or showcase row with the given cards, written straight to the table) are in `src/tests/helpers.ts`. `story` is in the TRUNCATE list in `src/tests/setup.ts`. Story tests are in `src/modules/story/story.test.ts` and `src/modules/admin/stories.test.ts`; the landing rules are in `src/modules/admin/site-content.test.ts` ("cards from submissions").

## Module boundaries (where agents commonly get stuck)

- **Auth routes** (`src/modules/auth/`): Google ID-token verification is frontend-driven. The backend only verifies the token via `jose`. Token signing is in `src/modules/auth/auth.service.ts`. An email listed in `super_admin_email` can sign in with POST /auth/google WITHOUT a role (no sign-up step); the first sign-in creates an ADMIN account with an ACTIVE SUPER_ADMIN admin_user. Other unknown accounts still get 404 "Sign up first".
- **Location**: `tutor_location` and `student_location` use PostGIS `GEOGRAPHY(POINT,4326)`. Coordinates are inserted via raw `ST_SetSRID(ST_MakePoint(lng, lat))` — do not switch to Prisma native geometry.
- **Files** (`src/modules/files/`, `src/lib/storage.ts`): R2 through the S3 API; only `storage.ts` imports the AWS SDK. `createUploadUrl` writes a PENDING_UPLOAD row and a 10-minute signed PUT that signs Content-Type and Content-Length (R2 refuses another type or size with 403; `presignPut` needs `signableHeaders` for content-length, which the presigner otherwise leaves unsigned); the browser PUTs to the private bucket; `completeUpload` checks the object (it exists, its size matches, its first 16 bytes match the type) and marks it UPLOADED. A feature attaches it with `claimFile(tx, ...)` inside its own transaction (400 INVALID_FILE for another owner, another purpose or a file not yet UPLOADED; 409 FILE_IN_USE when another record uses it). Limits live in `file-policy.ts` (`FILE_POLICY`: roles, types, max bytes; `MAX_UNUSED_UPLOADS` 10 counts uploads started in 24 h that are unfinished or finished but not attached, `MAX_TUTOR_VIDEOS` 3, `MAX_TUTOR_CREDENTIALS` 20). Story purposes: STORY_IMAGE (students and tutors, jpeg/png/webp, 5 MB) and STORY_VIDEO (students only, mp4/webm, 25 MB), see Stories. Site media purposes: SITE_IMAGE (admin, jpeg/png/webp, 5 MB) and SITE_VIDEO (admin, mp4/webm only, 25 MB), see Site content. `discardFile(tx, id)` marks a file DELETED inside the transaction; `removeObjects` runs after commit on both buckets, best effort, and failures are left to the cleanup cron. `fileUrl()` returns the public URL when the file is published, else a 1-hour signed GET; it is null without storage or when the file is not UPLOADED. `publishFile` and `unpublishFile` copy to and remove from the public bucket and run after commit only. Signed download URLs last 5 minutes and send `contentDisposition(name)`: an ASCII `filename` plus an RFC 5987 `filename*`, because raw non-ASCII names (Bangla) arrive garbled. `cleanFileName` in `file-policy.ts` cleans the upload's `fileName` in the schema (drops any path and Cc/Cf characters such as direction overrides, folds whitespace, shortens to 200 characters keeping the extension; empty becomes null). The cleanup cron locks each orphan row and re-checks `fileInUse` before deleting it, like `claimFile`, so a file attached during the sweep survives. An admin reading another owner's STUDENT_ID, TUTOR_ID or CREDENTIAL file is audited as `file.view`; admin deletes as `file.delete`. `hardDeleteAccount` reads the account's storage keys before its transaction and removes the objects after commit.
- **Upload moderation** (`src/modules/files/upload-review.service.ts`, `src/modules/admin/uploads.*`, `removeFile` in `src/modules/admin/files.service.ts`; migrations `20261126000100_upload_moderation` and `20261126000200_upload_moderation_validate`): table `upload_review` is the per-account history (action APPROVED | REJECTED | REVOKED | REMOVED | BLOCKED | UNBLOCKED; file name, type and size are copied so rows outlive the file; `purpose` is null only for BLOCKED and UNBLOCKED). Table `upload_block` holds one active row per account (protected index `upload_block_one_active`; at least one of `blocks_videos` and `blocks_documents`). Both tables and the tutor and student verification and video rows have `note` and `note_visible`. A hidden note is stored for admins and never returned to the user: `visibleNote` guards the tutor verification list, the tutor's own videos, the student owner response, `/me` and `GET /files/upload-status`. `app_notification.application_id` is nullable. CHECK `app_notification_application_shape` requires it for application kinds and forbids it for upload kinds (ID_APPROVED, ID_REJECTED, VIDEO_APPROVED, VIDEO_REJECTED, FILE_REMOVED, UPLOADS_BLOCKED, UPLOADS_UNBLOCKED). Upload alerts also carry `note`, `file_purpose`, `blocks_videos` and `blocks_documents`. Helpers in `upload-review.service.ts`: `uploadCategory` (TUTOR_VIDEO and STORY_VIDEO are VIDEOS; STUDENT_ID, TUTOR_ID and CREDENTIAL are DOCUMENTS; BLOG_COVER, SITE_IMAGE and SITE_VIDEO are never blocked), `assertUploadsAllowed` (403 UPLOADS_BLOCKED with `details.category` and `details.note`; called from `createUploadUrl` and `claimFile`, so a block placed mid-upload still holds), `recordUploadReview`, `notifyUpload` and `uploadFlagsFor` (rejections, revocations and removals in the last 30 days; `REPEAT_ISSUE_THRESHOLD` 3). Each write runs in the caller's transaction with its audit row; storage removal runs after commit.
  Decision state machine (`verifications.service.ts`): a tutor's decision applies only to the latest submission (submittedAt desc, id desc, as in the trigger). Students have no latest rule but need a submission. Allowed moves: PENDING to APPROVED or REJECTED, REJECTED to APPROVED, APPROVED to REJECTED (history REVOKED, the tutor's status follows the trigger). The same decision again, a non-latest tutor row, or APPROVE on a DELETED file gives 409 INVALID_VERIFICATION_STATE. REJECT needs a non-blank note.
  Removal (`POST /admin/files/:id/remove`): BLOG_COVER, SITE_IMAGE and SITE_VIDEO give 400 (site media is replaced in Site content). TUTOR_ID and STUDENT_ID: a PENDING ID is rejected; an APPROVED one is rejected only when `unverify` is true (default false). Only the latest tutor submission changes, and the row keeps its file id (`verification_file_id` stays for its CHECK). CREDENTIAL and TUTOR_VIDEO: the row that uses the file is deleted. Unused files are only discarded. Then `discardFile`, audit `file.remove`, history REMOVED, alert FILE_REMOVED; `removeObjects` runs after commit. The unused-only `DELETE /admin/files/:id` is unchanged.
  Blocks (`uploads.service.ts`; `GET /admin/accounts/:accountId/uploads`, `PUT .../upload-block`, `POST .../upload-block/lift`): `setUploadBlock` locks the account row, refuses ADMIN accounts (400 VALIDATION_ERROR) and updates the active block in place (blockedAt and blockedBy stay). `liftUploadBlock` gives 404 when nothing is active. Audit actions: `verification.decide`, `file.remove`, `uploads.block`, `uploads.unblock` (video moderation keeps `video.moderate`).
  `hardDeleteAccount` deletes the account's `upload_review` and `upload_block` rows before the profile deletes. An admin's history rows stay, with `actor_account_id` set to null (FK SET NULL).
- **Verifications**: tutor IDs are `tutor_verification` rows; the existing trigger `tutor_verification_sync` copies the latest status to `tutor.verification_status`. Student IDs are columns on `student` (`verification_file_id`, `verification_submitted_at`, `verification_decided_at`, `verification_reviewed_by`, `verification_note`); a resubmission clears the decision fields. Admin decisions lock the row first and write `verification.decide`. The student queue lists only rows with `verification_submitted_at` set.
- **Videos**: `tutor_video` rows start PENDING with `sort_order` = max + 1. `moderateVideo` locks the row and refuses a repeat decision (409 VIDEO_ALREADY_MODERATED); after commit it publishes the file (APPROVE) or unpublishes it (REJECT). Public lists and the public tutor profile show APPROVED videos only. `updateVideo` sets `sort_order` (audit `video.update`).
- **Blog**: public `/api/v1/blog` returns PUBLISHED posts only, with `publicCache`. `slugify` builds the slug from the title when none is sent; a duplicate slug (P2002) maps to 409 BLOG_SLUG_EXISTS. Covers are BLOG_COVER files owned by the admin, published after commit. Replacing or removing a cover leaves the old file to the cleanup cron. Only drafts can be deleted (409 INVALID_POST_STATE), and the draft's cover is discarded with it. The first move to PUBLISHED sets `published_at`.

  Profile phone change (`updateStudentProfile` and `updateTutorProfile`, one transaction): a different number takes `findVerifiedOtp` (verified for that number, unspent, within the 30-minute window). ## OpenAPI / Swagger

- `@fastify/swagger` (OpenAPI 3.1) is registered in `buildApp` before all routes via `registerOpenApi(app)`; zod schemas are the source of truth (`fastify-type-provider-zod` jsonSchemaTransform).
- Swagger UI at `/docs`, JSON at `/docs/json`. On by default outside production; off in production unless env `API_DOCS=true`.
- Every route spreads `...routeDocs({ tag, summary, description?, auth, errors?, rateLimit?, noContent?, deferred?, signedInCache? })` into its `schema`. `auth` is `"public" | "optional" | "any" | "admin" | role list`. `signedInCache` gives the signed-in Cache-Control text for an `optional` route that uses `sharedCache`. Error responses (shared `ErrorResponse` component) and 204s are injected only into the document by the swagger transform; the runtime serializer never sees them. 400 is added when a route validates input, 401 for signed-in routes, 403 for role/admin routes, 501 for deferred, 429 and 500 everywhere.
- Every route returning JSON must have a `response` zod schema. The zod serializer validates responses at runtime (strips undeclared fields, 500 on mismatch), so enum fields must use Prisma/education enums, `Date` objects use `z.date()`, un-converted Prisma `Decimal` uses `z.any().meta({ type: "string" })`.
- Reusable schemas get `.meta({ id: "PascalName" })`; request bodies are named by action without a suffix because the generator appends `Input` (e.g. id `"CreateZone"` → component `"CreateZoneInput"`). Unreferenced components are pruned. Paths are documented without trailing slash.
- `yarn openapi:export` writes the committed `openapi.json` at the repo root; `yarn openapi:check` fails when stale. CI runs openapi:check after typecheck; `.husky/pre-push` runs it too. `src/openapi/openapi.test.ts` fails if any route lacks tag/summary/auth/2xx schema (deferred 501 stubs exempt).
- Response schemas double as an allowlist: `GET /me` deliberately leaves out `googleSub` and `mfaSecretEnc`. Throw catalogue errors (`appError`, `notFound`); never `reply.send({ error, message })`, which has no `code`.

## What to avoid (quick list)

- Do not `prisma migrate reset` in shared/dev env — it destroys data.
- Do not accept Prisma-generated `DROP INDEX` for the indexes listed under Prisma / DB.
- Do not run `yarn test` without PostGIS on the test database.
- Do not forget to add new tables to the TRUNCATE in `src/tests/setup.ts` before committing.
- Do not modify `biome.json` rules without running `yarn lint` to verify.
